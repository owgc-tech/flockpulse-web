### Story Summary
Makes each tenant's invitation email subject and rich-text body fully configurable from the Community settings page, replacing the single hardcoded template every tenant currently shares. This requires switching the invite-sending mechanism itself: away from Supabase Auth's auto-sending `inviteUserByEmail()`, to generating the invite link separately and sending the actual email through the app's own new Mailtrap integration, using each tenant's configured template.

### Repo Target
Web (Next.js) — schema, backend send-path change, and admin UI. No mobile involvement.

### Grounding Check
Confirmed live against `owgc-tech/flockpulse-web` `dev`:
- `inviteMember()` (`invitation.service.ts`) currently calls `db.auth.admin.inviteUserByEmail(email, { redirectTo })` — this single call both creates the pending Supabase Auth user *and* auto-sends Supabase's own global email template. There is no separate "send" step to intercept — the send is baked into that one call.
- **No application-level email-sending code exists anywhere in this codebase** (confirmed via full-repo search) — Mailtrap is wired only at the Supabase project's own Auth SMTP settings, entirely outside this app's reach. This DIP is the first thing to ever send an email directly from application code.
- **No rich-text editor library is installed** (confirmed via `package.json`) — this is also net-new.
- `tenants` table already stores tenant-specific settings directly as columns (`description`, `logo_url`, `tagline` — no separate settings table) — `invite_email_subject`/`invite_email_body` follow the same precedent.
- `src/features/tenant/service.ts`'s `getTenantSettings()`/`updateTenantSettings()` and `app/api/tenant/settings/route.ts`'s GET/PATCH pair are the existing, correct places to extend — confirmed their exact current shape to mirror precisely, not guess at.
- `app/admin/(shell)/community/CommunitySettingsForm.tsx` (373 lines) is the existing settings page to add a new section to.
- Supabase's Admin API supports `generateLink({ type: 'invite', email, options: { redirectTo } })`, returning `data.properties.action_link` — this replaces `inviteUserByEmail()`'s auth-user-creation half without triggering its auto-send half. Everything else in `inviteMember()` (the `app_metadata` write, the `insertInvitation()` call, the duplicate-pending-invite guard) stays structurally unchanged.
- **Real external prerequisite, not covered by this DIP's code**: new Mailtrap API credentials, generated by Joseph and added as environment variables (locally and on Vercel), separate from whatever's configured in Supabase's own dashboard.

### Implementation Plan
1. **Migration**: `tenants.invite_email_subject TEXT`, `tenants.invite_email_body TEXT` (HTML). Seed every existing tenant with defaults matching Supabase's current built-in invite email wording as closely as reasonably possible, so no tenant's email silently changes on cutover.
2. **New `src/lib/email/mailer.ts`**: a small `sendEmail({ to, subject, html })` utility using `nodemailer` configured against the new Mailtrap credentials (env vars, to be provided by Joseph). Single-purpose, reusable by future email features.
3. **`src/features/tenant/service.ts`**: extend `getTenantSettings()`/`updateTenantSettings()` to include the two new fields, same validation conventions as existing settings fields.
4. **`app/api/tenant/settings/route.ts`**: extend GET/PATCH to pass through the two new fields, same pattern as existing ones.
5. **`invitation.service.ts`**: replace the `inviteUserByEmail()` call with `generateLink({ type: 'invite', email, options: { redirectTo } })`. After a successful link generation, fetch the tenant's configured subject/body, replace `{{invite_link}}` (and confirm at execution time whether `{{tenant_name}}`/`{{invitee_email}}` placeholders are also wanted) with real values, and call the new `sendEmail()` utility. The `app_metadata` write and `insertInvitation()` steps remain unchanged and still run after this.
6. **`CommunitySettingsForm.tsx`**: new "Invitation Email" section — plain text input for subject, a rich-text editor (Tiptap, a well-supported, lightweight React WYSIWYG library with no existing conflicting dependency in this app) for the body, storing/loading HTML. Include a visible note near the editor listing available placeholders (`{{invite_link}}`, etc.).
