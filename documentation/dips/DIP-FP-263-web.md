### DIP — FP-263 (Web): local scripts and Claude Code's dev server can never reach the hosted database

- **The mobile repo.** It has no scripts that write to a database.

### Story Summary
`.env.local` in this repo points at the **hosted** Supabase project `fpdb-dev`, which holds real OWGC data, with the service-role key. On 2026-11-19 a throwaway check by Claude Code read that file and created a stray tenant on `fpdb-dev`. Joseph has since removed it. Any test script or dev server started with those settings can change or delete real data, and the service-role key bypasses every access rule.

This DIP makes it structurally hard to repeat:
1. **A local-only guard** that every test script runs first, which refuses any database that is not on this computer;
2. **A `dev:local` command,** so Claude Code can run the app against the local Supabase without touching `.env.local`;
3. **An explicit opt-in for Joseph's maintenance scripts** that are meant for the hosted database;
4. **A standing rule in `CLAUDE.md`,** not `AGENTS.md`, because `next dev` rewrites `AGENTS.md`.

### Repo Target
Web (`owgc-tech/flockpulse-web`). Scripts, `package.json` and `CLAUDE.md` only. No migration.

### Implementation Plan
1. **Bootstrap.** Save this DIP verbatim to `documentation/dips/DIP-FP-263-web.md`. Create `feature/FP-263-local-db-guard` off current `dev`. Report the four grounding answers.

2. **Guard helper** `scripts/lib/assert-local-db.ts`, force-added:
   - `isLocalSupabaseUrl(url)` returns true only when the URL parses and its host is `127.0.0.1`, `localhost` or `[::1]`.
   - `assertLocalDb(url = process.env.NEXT_PUBLIC_SUPABASE_URL)`:
     - if the URL is not local, print `Refusing to run: this script only runs against the local Supabase (got host <host>). See CLAUDE.md.` and exit with code 1;
     - a missing URL is also refused.
   - There is no override flag. Test scripts must never reach a hosted database.

3. **Call the guard in every tracked test script:** `scripts/test-*.ts` and any other test-style script found in grounding item 1.
   - Add `assertLocalDb()` right after the lines that set `process.env`, and before any client is created or any app module that creates one is imported. If import order makes that impossible, use a top-of-file import that checks the values those scripts hardcode, and say which approach you used.
   - Do not change what the tests assert.

4. **Maintenance scripts** (`scripts/maintenance/*.mjs`). These are meant for the hosted database, so they need an explicit, typed opt-in:
   - if the URL is local, run as today;
   - if it is not, refuse unless the command line contains `--hosted=<project-ref>`, where `<project-ref>` matches the subdomain of the URL. Otherwise print the host and the exact flag needed, then exit with code 1;
   - keep the existing host printout.
   - `scripts/security/probe-direct-access.mjs` uses the anon key only and writes nothing. Leave it unchanged and say so.

5. **`dev:local` command:**
   - Add `scripts/dev-local.mjs`, force-added. It runs `supabase status -o env`, reads the local API URL, anon key and service-role key, and checks the URL with the same rule as the guard.
   - It starts `next dev` with `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` set in the **child process environment**, which overrides `.env.local` (grounding item 3). Use `NEXT_PUBLIC_SITE_URL=http://localhost:3000`.
   - It never writes a file and never prints keys. It works on Windows, so spawn with `shell: true` or the platform's `npx`.
   - If Supabase is not running, it says: "Start the local database first: supabase start".
   - Add `"dev:local": "node scripts/dev-local.mjs"` to `package.json`. Leave `"dev"` unchanged.

6. **`CLAUDE.md`:** keep `@AGENTS.md`, and add this section above it:
   ```
   ## Database safety (FP-263) — read before running anything
   - `.env.local` points at the HOSTED database with real data. Never read it into a script, never `source` it, and never start a dev server or script that uses it.
   - To run the app locally, use `npm run dev:local` (local Supabase only). Never `npm run dev`.
   - Every test script must call `assertLocalDb()` from `scripts/lib/assert-local-db.ts` before connecting. New test scripts must do the same.
   - Never apply migrations or run SQL against a hosted project. Joseph does that by hand.
   - If anything you ran may have touched a hosted database, stop and say so in your report.
   ```

7. **Test script** `scripts/test-fp263-local-guard.ts`, force-added. Pure checks of `isLocalSupabaseUrl`:
   - `http://127.0.0.1:54321` → true;
   - `http://localhost:54321` → true;
   - `https://abcd.supabase.co` → false;
   - `http://127.0.0.1.evil.com` → false;
   - `http://localhost.evil.com` → false;
   - `''` → false;
   - garbage → false.

   Also check:
   - running `assertLocalDb` in a child process with a hosted-looking URL exits with code 1;
   - every `scripts/test-*.ts` contains an `assertLocalDb(` call;
   - the maintenance script refuses a hosted URL without the flag and accepts it with a matching `--hosted=` flag. Use a fake URL with no network call, stopping before the client is created; add a `--dry-check` exit point if needed and say so.

8. **Checks:**
   - Run `npx tsc --noEmit`, lint and the new script.
   - Run a few existing test scripts against the local database to show the guard lets them through.
   - Run `npm run dev:local` with Supabase running: confirm the app loads at `localhost:3000` and that the server's Supabase host is `127.0.0.1`. Print the host only. Then stop the dev server.
   - `git diff dev --stat`. Confirm that `.env.local` is untouched (not in the diff and not modified on disk).

9. **Commit, push, and open the PR** with `gh pr create --base dev`.
